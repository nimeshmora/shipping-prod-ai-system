Part 2d · JSON 3 min

A way to write data as text, so it can travel.

{"name": "Ada", "age": 36}
  • { } wraps a set of facts about one thing
  • "name" is a label, always in double quotes
  • : separates the label from its value
  • , separates one fact from the next

Values: text (quoted), numbers (unquoted), true/false, or another { } nested inside.

$ echo '{"name":"Ada","age":36}' | python -m json.tool

{
    "name": "Ada",
    "age": 36
}

The | pipe

Takes what the left side printed and feeds it to the right side as input.

> sends output to a file. | sends output to another command.

Say this and stopThat is the whole purpose of JSON: a network can only carry text, so we agree on a way to write data down. Do not explain stdin.
Part 2d · Now break it on purpose

The error tells you the rule.

$ echo "{'name':'Ada'}" | python -m json.tool

Expecting property name enclosed
in double quotes: line 1 column 2
JSON labels need double quotes. Always.

Single quotes are legal in Python and illegal in JSON. This is the single most common JSON mistake.

If anyone knows Python

It looks exactly like a dict. The two differences that bite: double quotes only, and no trailing comma.

Why this is worth 30 secondsThey have now made this mistake deliberately. The error message that would confuse them in Week 4 is one they have already seen and understood.
Part 2e · curl 6 min · the highest-value minutes today

A browser with no window.

It sends a request over the network and prints what came back.

You will use it in every session from here. So learn it on something simple first, where nothing else can be the problem.

ONE — fetch a web page
$ curl -s https://example.com

<!doctype html><html lang="en"><head>
<title>Example Domain</title>...
...a pile of HTML, all one line.

That is what a web page IS underneath — text your browser draws. You have just done what a browser does.

-s = silent; without it curl prints a progress bar that gets in the way.

Why this beat existsThe reason is diagnostic, not comfort. When a three-flag POST fails in Beat 5, a student who ran these five toys can tell "my JSON is malformed" from "my flags are wrong" from "the service is down". One who cannot will raise their hand for every failure for eight weeks.

No internet? python -m http.server 9000 in one terminal, curl -s localhost:9000 in another covers points 1–4.

Part 2e · Three — what a reply is made of

Three things arrive, every time.

$ curl -s -i https://api.github.com/zen

HTTP/2 200
date: Mon, 31 Aug 2026 05:04:25 GMT
content-type: text/plain;charset=utf-8

Keep it logically awesome.
HTTP/2 200 ◀── a STATUS: how it went content-type: text/plain ◀── HEADERS: facts about the reply (blank line: headers end here) Keep it logically awesome. ◀── the BODY: the actual answer
Say this-i includes the headers. Headers are extra facts about the request or reply that are not the body itself. content-type is how the receiver knows what kind of thing it just got. That is the whole idea.
Part 2e · Four — make failures happen

Same command. Different numbers.

$ curl -s -o /dev/null \
    -w "%{http_code}\n" \
    https://httpbin.org/status/404

404

Now try 200. Then 500.

Two flags worth keeping

-o /dev/null — throw the body away, we do not care about it

-w "%{http_code}" — print just the status code

You use -w "%{http_code}" heavily in Week 3.

Do now, and do NOT explain the numbersHave them run all three — 200, 404, 500. That is what turns status codes from a table on a slide into something real.

The meaning comes in Beat 4, twenty minutes from now, and it lands far better as "remember the 404 you made?" than as a table nobody has a memory attached to.
Part 2e · Five — send something

Keep this command. We change one thing later.

$ curl -s -X POST https://httpbin.org/post \
    -H 'Content-Type: application/json' \
    -d '{"message":"hello"}'

{
  ...
  "json": {
    "message": "hello"
  },
  ...
}
  • -X POST — we are sending, not just reading
  • -H — a header: "the body I am sending is JSON"
  • -d — the body. The actual thing being sent.
The server received your JSON, understood it, and read the message field out.
Write this promise on the board"Keep that command. In Beat 5 we change the URL to your own laptop, and the answer comes back from your agent instead of an echo service. Nothing else about the command changes."

Your secrets stay yours

Anything can call it

Beat 4 · Idea 2 · the turn it makes

From a program to a service.

A program
  • you run it
  • it does its job
  • it exits
  • one user: you
  • crashes are your problem
A service
  • it is already running, waiting
  • it does its job when asked
  • it never exits
  • many users, at once, strangers
  • crashes are everyone's problem
Everything difficult in the next eight weeks comes from that right-hand column.

Memory that must outlive a restart (Week 2). Strangers (Week 3). Costs that scale with users you never met (Week 4). Knowing it is healthy when nobody is watching (Week 5).

Point at the right column"That is the whole syllabus. Not one line of it is about AI." This is the best moment in the course to answer "why am I here?" for students who arrived expecting more prompt engineering.

Row three, for free: "You ran sleep 30, a program that refused to exit, and it annoyed you. A server does that forever, on purpose."

Beat 4 · Idea 3 of 5

How one computer finds another.

a phone number +94 71 234 5678 an IP address 172.217.24.206

Every computer on the internet has a number. But nobody remembers numbers — so we use names, and something looks the name up for us.

you want you need the lookup ────────── ─────────────── ────────── "Mum" +94 71 234 5678 contacts "google.com" 172.217.24.206 DNS
DNS is the internet's contacts list.
$ ping -c 1 google.com

PING google.com (172.217.24.206): 56 data bytes
↑ a name just became a number
$ ping -c 1 this-name-does-not-exist-xyz.com

ping: cannot resolve ...: Unknown host

"Cannot resolve" means the contacts list had no entry. Not "the computer is down" — nobody even found out where to knock.

Keep it to three commandsThis is the one concept in Beat 4 with its own toy, because it is the one they did not do in Beat 2.

Different numbers? "Big sites answer from many machines around the world, and DNS hands you a nearby one. You and the person next to you are talking to different computers, and both of you are right."

The ms figure makes distance physical: same city = single digits, another continent = 200+. "Nothing is instant. It is just fast." That is the seed of Week 5's p95.

Part 1 · The session ID, drawn

Part 1 · The error you will see most — every week

KODEKEY is not set

What an environment variable is

A setting that lives outside your code, attached to the terminal session, that a program can read when it starts.

It is how you give a program a secret without typing the secret into a file that gets shared.

$ export GREETING=hello
$ python -c "import os; print(os.environ.get('GREETING'))"
hello
$ python -c "import os; print(os.environ.get('NOPE'))"
None
KODEKEY is not set means exactly what that second line printed.

The fix — in the same terminal as make run

$ set -a && source .env && set +a

That reads your .env file — the hidden dotfile you met with ls -la in Part 2a — and exports every line in it.

Write this on the board and leave it for eight weeksThirty seconds on export now, and KODEKEY is not set stops being mysterious for the rest of the course.

Part 2 · What you build in app/stream.py

One open connection, many small events.

ONE OPEN CONNECTION, over 8 seconds ─────────────────────────────────────────────────────────▶ event: start the turn was accepted — session id + turn id event: status something happened (a tool ran) event: token "Your standing desk arrives" ┐ event: token " on Thursday the 4th, and" │ a chunk of event: token " tracking is available now." ┘ the answer event: done finished — steps, tokens, cost, duration (or, if it goes wrong halfway) event: error it failed — and this is always the LAST frame

Trap 1 · The blank line after each piece is not optional

It is what tells the receiver "that piece is complete". Leave it out and the client waits forever for something you already sent.

Three traps, all caught by the checkpointThis slide has the first. Next slide has the second, which is the conceptually hard one. The third is the buffering they just watched.
Part 2 · Trap 2 · the one worth slowing down for

An error mid-stream cannot be an error code.

NORMAL MID-STREAM FAILURE ────── ────────────────── status 500 ◀── possible status 200 ◀── already sent! too late. {"detail": …} event: token … event: token … event: error ◀── the ONLY way left to say it

By the time the model fails, you already said "200, here it comes". There is no status code left to change.

The error has to arrive as another piece of the stream — and the client has to read it.

Trap 3 · Proxies buffer

Something between you and the user will collect your whole streamed answer and deliver it in one lump — silently, because the answer is still correct.

X-Accel-Buffering: no is how you tell a proxy not to.

Why trap 2 mattersMiss it and a broken agent shows the user half an answer and calls it success. Your dashboard will report a healthy service while users see truncated replies.

Trap 3 callback: "You just watched exactly this happen — curl with no -N."

"Works on my machine" is not a deployment.

WHAT YOU HAVE NOW WHAT A CONTAINER IS ───────────────── ─────────────────── your code ┌──────────────────────┐ + hope that the │ your code │ other machine has: │ the libraries │ - the right Python │ the right Python │ - the right libraries │ a whole Linux │ - the right layout └──────────────────────┘ - the right env vars one thing. runs anywhere.
A container is a box holding your code and everything it needs to run. Hand the box to any computer and it behaves identically.

Part 3 · Toy first — a box with nothing in it

Two files. Four lines.

$ mkdir ~/box && cd ~/box
$ echo 'print("hello from inside the box")' > hello.py

You already know mkdir and echo > from Part 2b.

# Dockerfile  (no extension — that exact name)
FROM python:3.12-slim
WORKDIR /app
COPY hello.py .
CMD ["python", "hello.py"]
  • FROM — start from a box that already has Python 3.12. Somebody else built that; we build on top.
  • WORKDIR — work in /app inside the box.
  • COPY — copy our file from our computer into the box.
  • CMD — what to run when the box starts.
$ docker build -t hello-box .
$ docker run --rm hello-box

hello from inside the box
Unpack that output — the significance is easy to miss"That print ran on a Linux machine with a Python you did not install, in a folder that does not exist on your laptop. And it will print exactly that on anyone else's computer too."

build = make the box (-t names it, . means "Dockerfile is here"). run = start it (--rm = throw it away when it exits).

Delete the file. Run it again.

$ docker run --rm hello-box

hello from inside the box
↑ it STILL prints.
The code was copied into the box at build time.

The box is not pointing at your folder. It contains a copy.

Part 3 · Now the real one

The same four ideas, plus three lines.

FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
ENV PORT=8080
EXPOSE 8080
CMD exec uvicorn app.main:app \
      --host 0.0.0.0 --port ${PORT}
  • RUN does something while building. CMD runs when the box starts.
  • ENV sets an environment variable — same thing you met with KODEKEY.
  • EXPOSE documents which door the thing inside listens on.

--host 0.0.0.0 — accept connections from outside the box. The default only accepts them from inside, so the platform's health check could never reach you.

exec — makes uvicorn the main process, so "please shut down" actually reaches it. Without it the platform waits, gives up, and kills you: a slow, ugly deploy every single time.

Two lines carry the whole lessonThe COPY order, and ${PORT}. Both on the next slide — do not let them get lost in the flag details.
Part 3 · The two lines that carry the lesson

Order matters, and hardcoding hurts later.

THE ORDER WE USE THE OBVIOUS-LOOKING ORDER ──────────────── ───────────────────────── COPY requirements.txt COPY . . ← your code RUN pip install ← slow RUN pip install ← slow COPY . . ← your code edit one line of code: edit one line of code: pip install is CACHED pip install RUNS AGAIN rebuild: 3 seconds rebuild: 3 minutes

--port ${PORT}, never --port 8080

Every hosting platform tells your service which door to use, through a setting. Hardcode the number and you have a service that works on your laptop and fails the moment you deploy it.

Docker remembers each step...and redoes every step after the first thing that changed. Copy your code first and every one-character edit reinstalls every library.

Early finishers can add a second file to the ~/box toy, rebuild, and watch only the changed step re-run. The caching lesson, felt rather than described.
Part 3 · .dockerignore · and the line that matters most

Never put a secret in a container.

# .dockerignore
.venv/
.git/
__pycache__/
.env

A list of things NOT to copy into the box. Without it, COPY . . copies everything in the folder.

That last line matters most.

Without it, your API key gets baked into the box. Boxes get copied, cached, and uploaded to servers other people can read.
